1. Why must the client read a 220 reply before sending HELO?
    - The client must read a 220 before sending HELO to ensure that the server is ready to begin the SMTP conversation.

2. Why is 354 a correct response to DATA even though it does not begin with 2?
    - 354 is the correct response because it indicates that the server is ready for the message headers and body, so the client should continue sending the message.

3. If RCPT TO receives 550, should the client send DATA? Explain.
    - No, because a 550 response indicates a permanent failure with the recipient, so the client should not continue to the DATA command.

4. A client sends DATA immediately after HELO. The server returns 503 Bad sequence of commands. Explain the error and give the correct sequence.
    - The error occurs because DATA was sent before the sender and recipient were specified. The client must first send MAIL FROM and RCPT TO before sending DATA. The correct sequence is HELO → MAIL FROM → RCPT TO → DATA.

5. After the DATA block, the server returns 250 Message accepted for delivery. Does this prove that the message appeared in the recipient’s inbox?
    - No, it only proves that the SMTP server accepted the message for delivery, not that the message was delivered to the recipient's inbox.

6. A message body contains:
        First line
        .
        Last line
    What happens if the client sends this without dot-stuffing? How should it be encoded?
    - Without dot-stuffing, the server would interpret a . on its own line as the end-of-message marker, so the client sends it as .. to show that the dot is part of the message body.
